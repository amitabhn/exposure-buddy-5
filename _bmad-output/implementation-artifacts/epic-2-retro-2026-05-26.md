## Challenges

### 1. Async race conditions in `useEffect` — 3/3 stories

Every story had at least one `useEffect` body with a Promise inside it where the concurrency case (second call before first resolves) wasn't guarded:

- **2.1 P2:** Resend button didn't set `isLoading` — concurrent OTP calls possible
- **2.2:** No loading guard during consent write — rapid double-tap could trigger concurrent writes
- **2.4 P1:** `signOut()` called fire-and-forget (no `await`) in deletion guard

All caught in code review and patched. The pattern is subtle — the happy path works; the race is only visible under concurrent input. The issue is systemic, not a knowledge gap.

### 2. `useEffect` dependency arrays — 2/3 stories

- **2.2:** `isNewAccount` missing from dep array — stale closure risk in strict mode
- **2.4:** Dep array extended to include `pendingDeletion` and `signOut`

The `eslint-plugin-react-hooks/exhaustive-deps` rule should catch this at lint time. If it's set to `warn` rather than `error`, it gets silently ignored.

### 3. ARC-011 boundary violations caught in review — 2/3 stories

- **2.2:** `"dom"` lib added to `packages/core/tsconfig.json` to get `console` types — silently makes browser globals available, undermining the ARC-011 zero-framework boundary. Fixed: explicit `console` declaration in `globals.d.ts`, `"dom"` removed.
- **2.4:** `AuthProvider` directly constructed `new DpoServiceStub(...)` instead of receiving `IDpoService` via injection — violated the "stub is injected" ARC-011 contract. Fixed: `dpoService?: IDpoService` prop added.

### 4. Environment friction repeated across stories

`__DEV__` undefined in `packages/core` Vitest environment hit in both Story 2.2 and 2.4 as independent discoveries. `en.json` duplicate `nav` key collision in 2.4 (despite 2.2 already touching that file). No local environment runbook exists — each story discovered the same setup friction independently.

This is the highest-leverage fix before Epic 3, which adds a fourth runtime (Deno for Edge Functions) to the existing three (Metro, Vitest, Jest).

---

## Key Insights

1. **The stub interfaces were the right architectural bet.** The plan held. Epic 3 slots in exactly where the architecture said it would — no rework, just swap.

2. **Review catches everything, but 'everything' is too late.** 21 patches across 3 stories is the cost of catching async races and dep array issues post-implementation. Two of those three patterns are addressable at the tooling level.

3. **Environment setup is a hidden time sink.** Getting the app to a running state cost meaningful time on every story. With Epic 3 adding Deno/Supabase CLI complexity, this needs to be documented once rather than rediscovered story by story.

4. **Story 2.2's DPDPA isNewAccount decision is the quality bar.** Multi-agent reasoning, explicit decision record, consequence analysis. That's the standard for compliance-adjacent decisions going forward.
