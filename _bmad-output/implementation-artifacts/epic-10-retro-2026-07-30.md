## Successes

**The bug-chain discipline held three times in a row.** Story 10.2's code review found the `perform_user_erasure()` NOT NULL bug mid-review and explicitly deferred it rather than expanding scope → Story 10.4 fixed it as its own focused fast-follow → Story 10.4's *own* code review then found the re-erasure idempotency gap the fix had newly exposed, and deferred *that* too → Story 10.5 fixed it. Three consecutive "found mid-review, spun out, didn't scope-creep" decisions, each one correctly triaged and each one delivered as a small, well-scoped story. This is the same pattern the Epic 5 retro called out as needing discipline (via the story-size gate) — it's now visibly working end-to-end.

**Patch counts trended down as the epic's own conventions matured.** 10.1's implementation review needed 10 patches; by 10.5 the same three-layer review (Blind Hunter, Edge Case Hunter, Acceptance Auditor) found 0 patches and only 1 decision-needed. The MCP-based hosted-verification pattern (`apply_migration` + `list_migrations`, since `supabase link` can't authenticate in this environment) was established in 10.2 and reused verbatim in 10.4 and 10.5 without rediscovery.

**A real, silent DPDPA compliance gap got closed.** `perform_user_erasure()` — the actual "right to erasure" implementation — had been failing on every invocation since Epic 3. It was found not by a targeted audit but as a side effect of an unrelated hardening story writing an EXECUTE-privilege test. That test earning its keep this way is a strong argument for the RLS/pgTAP test-harness investment (ADR-006) generally.

**Consent-recording parity was treated as seriously for the password path as the OTP path.** Story 10.1's "Consent Recording Race" — ensuring `ConsentRecordService.recordConsent` and `emitAccountCreated` fire before redirect on password signup, mirroring the OTP flow exactly — got its own Dev Notes section, an explicit AC, and a dedicated ref-guard implementation. This wasn't treated as a footnote next to the "real" feature work.

## Challenges

### 1. The erasure bug was invisible for multiple epics with zero functional test coverage
`perform_user_erasure()` shipped in Epic 3 and was never exercised by an automated test that checked it actually succeeded — only EXECUTE-privilege (grant-level) tests existed, and only because Story 10.2 added one incidentally. For a DPDPA §5 "right to erasure" feature, that's a long window where a real erasure request would have silently failed with no automated signal. This isn't a criticism of any one story — it's a gap in test-coverage strategy for compliance-critical RPCs generally.

### 2. Local infra churn ate real time across three stories
- `supabase link` fails in this environment (no `SUPABASE_ACCESS_TOKEN`, no browser OAuth) — hit fresh in 10.2, worked around with MCP tools, and had to be re-confirmed in 10.4 and 10.5.
- A stale Docker container/volume set under the old `project_id` ("exposure-buddy") was flagged and "fixed" in 10.2's code review, but the fix didn't fully stick — Story 10.4 hit the same stale-stack problem again and had to redo the cleanup.
- The local `edge-runtime` container has been unable to boot **any** Edge Function since Story 10.4 (`BOOT_ERROR`, `failed to determine entrypoint`). Still unresolved as of 10.5. Story 10.5's AC #2 verification had to fall back to code reading instead of a live HTTP call as a direct consequence.

None of these blocked delivery, but all three are the kind of infra friction that's cheap to fix once and expensive to keep working around story after story.

### 3. Story 10.3 is done in name only for real users, and untraceable as a story
Two separate issues on the same story:
- **Functionally:** the forgot/reset-password flow is code-complete and tested but still hidden behind `EXPO_PUBLIC_ENABLE_PASSWORD_RESET` (default off) because custom SMTP isn't provisioned. Epic 10 is marked "done," but one of its two headline user-facing capabilities (FR-AUTH-05) is invisible to any real user today.
- **Procedurally:** unlike 10.1, 10.2, 10.4, and 10.5, there is no `_bmad-output/implementation-artifacts/10-3-*.md` story file. Its content lives only in `epics.md`'s Story 10.3 section and the old `feature/password-based-login` branch. A future audit or retro looking for "the 10.3 story" the way it can find the other four will find nothing.

### 4. Four epics in a row skipped their retrospective
Epics 6, 7, 8, and 9 all left `epic-N-retrospective: optional` unactioned. It happened to work out this time (both spot-checked Epic 5 action items were in fact addressed), but that's luck, not process — a critical action item (like Epic 5's B1) could just as easily have quietly dropped for four epics with nobody checking.

## Key Insights

1. **A grant-level test and a functional test are not the same thing, and the gap between them can hide a broken compliance feature for a long time.** Story 10.2's EXECUTE-privilege test proved *who* could call `perform_user_erasure`, not that calling it *worked*. Worth an explicit check: are there other DPDPA-critical paths (e.g. `dpo-export-user`, `dpo-pending-requests`, the consent-record write itself) with the same shape of gap — reviewed and shipped, but never asserted to functionally succeed end-to-end?

2. **The "defer as fast-follow, don't scope-creep" discipline is the single best thing that happened this epic**, and it happened three times, not once. Worth calling out explicitly as a pattern to keep protecting, not just something that happened to work.

3. **Infra friction that gets "fixed" in a code review patch should be verified as actually fixed, not just patched.** The stale-Docker-stack issue was patched once (10.2) and recurred (10.4) — a one-line "confirm resolved" step in a later story's Dev Notes would have caught the recurrence before it cost time again.

4. **A story with no story file is a silent gap in the project's own record-keeping**, independent of whether the feature itself works. 10.3 should get a retroactive story file even though the code is already merged, purely so the project's traceability convention (one story file per delivered AC set) doesn't have a hole in it.

5. **Skipping a retro isn't free even when nothing goes wrong.** Four consecutive skips (Epics 6–9) meant Epic 5's action items went unchecked for that whole span. This retro's spot-check was cheap and found no damage — but that's not something to rely on happening again.
